Logic Synthesis와 제약

16-1. 합성의 단계

Parameter와 generate는 먼저 구조를 결정하고 optimization은 관측 동작을 보존하면서 회로를 바꾼다. 최종 결과는 제약과 target library의 영향을 받는다.

계산·동작 예

a+b를 두 곳에서 사용한 RTL이 공유되거나 복제되는지는 타이밍·자원 조건에 따라 달라질 수 있다. RTL 줄 수가 cell 수를 직접 뜻하지 않는다.

시뮬레이터에서 실행된 모든 language construct가 합성 가능한 것은 아니다.

언어 구조와 생성 회로의 관계를 설명한다.

16-2. SDC의 기본

생성 clock은 실제 원천과 관계를 정의해야 한다. IO delay는 칩 밖의 launch/capture와 board 조건을 내부 timing 분석에 연결한다.

계산·동작 예

Clock period를 정한 뒤 input delay와 output delay를 외부 소자·배선 예산에서 계산한다. 누락된 endpoint와 unconstrained path를 별도로 확인한다.

코드와 동작

# 아래 값은 설명용 가정입니다. 실제 설계의 IO 예산으로 바꾸세요.
create_clock -name clk -period 10 [get_ports clk]
set_input_delay  -clock clk -max 2.0 [get_ports data_in*]
set_input_delay  -clock clk -min 0.2 [get_ports data_in*]
set_output_delay -clock clk -max 1.0 [get_ports data_out*]
set_output_delay -clock clk -min -0.1 [get_ports data_out*]
# 단위와 실제 보드/외부 소자의 max/min 예산을 확인하세요.

제약이 없어서 violation이 없다는 결과를 timing 성공으로 읽지 않는다.

모든 timing endpoint의 가정을 명시한다.

16-3. 예외 제약과 검증

예외를 넣으면 보고서가 좋아질 수 있지만 잘못된 예외는 실제 실패 경로를 숨긴다. 예외마다 신호·mode·검증 근거를 기록한다.

계산·동작 예

다른 cycle에만 사용되는 데이터라면 enable과 capture 관계가 실제로 보장되는지 확인한다. Multicycle setup을 바꿀 때 hold 관계도 함께 검토한다.

Timing을 통과시키기 위해 원인 분석 없이 false path를 추가하지 않는다.

예외마다 설계 근거와 검증 방법을 기록한다.

다음 절 · 회로 추론과 자원 공유

16-4. 회로 추론과 자원 공유

Resource sharing은 면적을 줄일 수 있지만 mux와 schedule 제어를 추가한다. 반대로 복제는 병렬성을 늘리면서 load와 전력을 바꾼다.

계산·동작 예

두 연산이 같은 cycle에 필요하면 하나의 multiplier로 공유하려면 실행 schedule이나 clock 조건을 바꿔야 한다. 기능만이 아니라 throughput 계약을 확인한다.

면적이 줄었다는 이유로 동일 latency·처리율을 유지한다고 가정하지 않는다.

면적·지연·전력 변화를 근거로 판단한다.

16-5. PPA 최적화와 리포트

동일한 corner·constraint·library에서 전후를 비교해야 효과를 해석할 수 있다. Logic depth, fanout, wire estimate와 register 위치를 함께 본다.

계산·동작 예

긴 priority chain을 균형 구조로 바꾸거나 pipeline을 추가하는 대안을 비교한다. Pipeline 추가는 timing을 개선할 수 있지만 latency와 상태 관리가 바뀐다.

다른 clock constraint로 얻은 면적 수치를 개선 전후로 직접 비교하지 않는다.

최적화 전후를 동일 제약으로 비교한다.

16-6. LEC와 합성 인계

Reset·clock·black box·matching point와 환경 가정이 결과에 영향을 준다. 합성 인계에는 netlist뿐 아니라 library·constraint·버전 정보가 필요하다.

계산·동작 예

RTL과 합성 netlist가 실패한 compare point를 갖는다면 단순 이름 차이인지 실제 logic 차이인지 cone과 초기 상태를 확인한다.

Unmatched point를 모두 무시한 채 PASS를 얻는 것을 검증 완료로 보지 않는다.

합성 결과의 동치와 인계 파일 완전성을 확인한다.
