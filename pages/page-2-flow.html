Part 2

Design Flow

2-1. Design to Product Flow
STAGE 01

제품 정의 (Spec)

시장 타겟 PPA(Power, Performance, Area) 결정 및 시스템 아키텍처 수립

STAGE 02

논리 설계 (RTL)

마이크로 아키텍처 설계, Verilog/SystemVerilog 기반 코딩 및 IP 통합

STAGE 03

검증 & 합성

UVM/Formal 기반 기능 검증(DV) 후 Gate-level Netlist 변환 및 DFT 삽입

STAGE 04

물리 설계 (PD)

Floorplan, P&R, STA 튜닝, DRC/LVS 및 IR-Drop 검증 완료 후 GDS 확보

STAGE 05

Tape-out & Fab

Foundry로 설계 이관, 마스크 제작 및 웨이퍼 레벨 대량 생산 진행

STAGE 06

Post-Si 검증

양산된 실물 칩을 보드에 실장하여 S/W 연동 디버깅 및 시스템 신뢰성 최종 테스트

각 단계에서 무엇이 들어오고, 어떻게 바뀌고, 무엇이 나오는지

9개 단계 · 그림으로 따라가는 설계 흐름
01

Spec / Architecture

요구사항을 설계 가능한 구조로 구체화

INPUT

  • Product requirement

    제품이 만족해야 할 기능·성능·제약

  • Application / market

    응용 분야와 시장에서 필요한 조건

  • Target use-case

    대표 사용 시나리오와 동작 환경

PROCESS

  1. Use-case
  2. PPA
  3. IP / Blocks
  4. Interfaces

OUTPUT

  • Architecture spec

    시스템 구조와 설계 목표 명세

  • block diagram

    기능 블록과 인터페이스 연결도

  • top-level requirement

    상위 기능과 성능의 요구사항

단계별 핵심 과정

  1. 01
    Use-case / 기능 범위

    제품이 수행할 기능과 외부 시스템의 경계를 정합니다. 어떤 상황에서 쓰이는지부터 확인합니다.

  2. 02
    PPA 목표 설정

    Power·Performance·Area 사이의 균형을 잡고 각 블록에 목표를 배분합니다.

  3. 03
    IP / 블록 구조

    필요한 IP를 선택하고 기능을 블록과 계층 구조로 나눕니다.

  4. 04
    인터페이스 정의

    블록 사이에 주고받는 데이터, 제어 신호, 프로토콜의 기준을 정합니다.

정의한 구조와 요구사항이 RTL 설계의 기준이 됩니다.

02

RTL / HDL Coding

설계 구조를 클록에 따라 동작하는 RTL로 표현

INPUT

  • Architecture spec

    기능 블록과 동작 구조의 명세

  • block diagram

    상위·하위 모듈 및 연결 관계

  • top-level requirement

    기능·성능·동작 조건

PROCESS

  1. Hierarchy
  2. Clock / Reset
  3. Datapath
  4. Interface

OUTPUT

  • RTL source

    Verilog / SystemVerilog 등 설계 소스

  • interface definition

    포트·신호·프로토콜 정의

  • early constraint

    초기 클록과 타이밍 제약

단계별 핵심 과정

  1. 01
    Module / Hierarchy

    아키텍처를 RTL 모듈로 분할하고 상위·하위 모듈의 연결을 코드로 구현합니다.

  2. 02
    Clock / Reset

    클록 에지에서 바뀌는 상태와 리셋 시 초기값을 명확하게 정의합니다.

  3. 03
    Register / Datapath

    레지스터와 조합 논리를 구분해 데이터가 어떻게 계산되고 저장되는지 표현합니다.

  4. 04
    Interface / Assertion

    포트와 Register map을 정리하고, 기본 동작 규칙을 확인할 Assertion seed를 준비합니다.

작성한 RTL과 인터페이스 정의를 기능 검증에 전달합니다.

03

DV / Functional Verification

다양한 시나리오로 RTL의 기능과 경계 조건을 검증

INPUT

  • RTL source

    기능을 검증할 설계 소스

  • interface definition

    입출력 신호와 프로토콜 기준

  • verification plan

    검증 대상 기능과 종료 기준

  • testbench / scenario

    검증 환경 및 테스트 시나리오

PROCESS

  1. Testbench
  2. Simulation
  3. Debug
  4. Coverage

OUTPUT

  • Verified RTL

    검증 계획의 종료 기준을 만족한 RTL

  • bug fix log

    발견한 오류와 수정 이력

  • verification signoff state

    커버리지와 검증 종료 상태

단계별 핵심 과정

  1. 01
    UVM / Testbench

    검증 환경과 시나리오를 구성합니다. Driver·Monitor·Scoreboard의 역할을 나눕니다.

  2. 02
    Simulation

    입력 자극을 적용하고 출력 파형과 트랜잭션을 확인합니다.

  3. 03
    Debug loop

    기대 결과와 실제 결과가 다른 지점을 찾아 RTL을 수정하고 다시 검증합니다.

  4. 04
    Coverage closure

    기능·경계·오류 조건의 커버리지를 확인하고 합의된 검증 종료 기준을 충족합니다.

기능 검증을 마친 RTL이 Logic Synthesis의 입력이 됩니다.

04

Logic Synthesis

RTL을 표준 셀 기반의 게이트 회로로 변환

INPUT

  • Verified RTL

    기능 검증을 완료한 RTL

  • SDC constraint

    클록과 입출력 등 타이밍 제약

  • Std cell library

    사용할 표준 셀과 특성 정보

  • Power intent

    전원 도메인 등 전력 설계 의도

PROCESS

  1. Compile
  2. Library mapping
  3. Optimization
  4. STA sanity

OUTPUT

  • Gate-level netlist

    표준 셀과 연결 관계의 넷리스트

  • timing report

    경로 지연과 타이밍 분석 결과

  • area / power report

    합성 기준 면적·전력 분석 결과

단계별 핵심 과정

  1. 01
    Compile / Elaboration

    RTL을 해석해 레지스터와 연산자 등 하드웨어 구조를 추출합니다.

  2. 02
    Library mapping

    추출한 논리를 표준 셀 라이브러리에 있는 게이트와 플립플롭으로 매핑합니다.

  3. 03
    PPA Optimization

    논리 동등성을 유지하면서 타이밍·면적·전력을 조정합니다.

  4. 04
    STA sanity

    주요 타이밍 경로와 제약 적용 상태를 확인해 합성 결과의 이상을 점검합니다.

Gate-level netlist에 테스트 구조와 구현 제약을 더합니다.

05

DFT / PI

테스트 구조와 전원 의도를 반영해 물리 구현을 준비

INPUT

  • Gate-level netlist

    합성된 게이트 수준의 넷리스트

  • timing report

    합성 타이밍 분석 결과

  • test requirements

    스캔 방식과 테스트 요구사항

  • low-power intent

    저전력 동작과 전원 도메인 의도

PROCESS

  1. Scan insertion
  2. UPF
  3. Constraints
  4. Sanity

OUTPUT

  • Scan-ready netlist

    테스트 구조를 반영한 넷리스트

  • test structure

    스캔 체인과 테스트 로직 정보

  • implementation-ready constraints

    물리 구현에 사용할 정리된 제약

단계별 핵심 과정

  1. 01
    Test logic insertion

    스캔 체인 등 테스트 로직을 삽입해 내부 상태를 제어·관찰할 수 있도록 준비합니다.

  2. 02
    UPF / Power intent

    전원 도메인과 저전력 동작을 정의하고 도메인 경계의 처리를 정리합니다.

  3. 03
    Refined constraints

    기능 모드와 테스트 모드에 맞춰 클록·타이밍·전원 제약을 구체화합니다.

  4. 04
    Sanity check

    스캔 연결, 테스트 구조, 전원 의도와 제약의 일관성을 확인합니다.

테스트와 전원 의도를 반영한 설계를 Physical Design에 전달합니다.

06

Physical Design

논리 회로가 실제 칩의 배치와 배선으로 바뀌는 과정

INPUT

  • Implementation-ready netlist

    테스트 구조 등을 반영한 넷리스트

  • Constraint

    타이밍과 물리 구현 제약

  • UPF

    전원 도메인과 저전력 정보

  • Design kit / target

    공정 라이브러리·기술 파일·목표

PROCESS

  1. Floorplan
  2. Placement
  3. CTS
  4. Routing

OUTPUT

  • Placed / routed DB

    배치·배선이 완료된 설계 DB

  • extracted RC

    배선의 기생 저항과 커패시턴스

  • closure report

    타이밍·전력 등 수렴 결과

단계별 핵심 과정

3D 구조를 불러오는 중입니다.

드래그로 회전 · 휠로 확대 · 방향키로 회전 구조와 흐름을 보는 개념 모델

  1. 01
    Floorplan

    칩 영역, 매크로, IO와 전원 구조를 계획하고 표준 셀을 배치할 공간을 확보합니다.

  2. 02
    Placement

    표준 셀의 위치를 정합니다. 타이밍과 혼잡도를 함께 고려합니다.

  3. 03
    CTS

    클록이 각 플립플롭에 전달되도록 트리를 구성하고 지연과 스큐를 조정합니다.

  4. 04
    Routing / Extraction

    셀 사이를 배선하고 기생 RC를 추출합니다. 분석 결과에 따라 ECO를 반복합니다.

배치·배선 DB와 추출 RC를 Signoff 검증에 전달합니다.

07

Signoff

타이밍·물리 규칙·전원 무결성을 확인하고 최종 승인

INPUT

  • Placed / routed DB

    최종 배치·배선 설계 데이터

  • extracted RC

    타이밍·전원 분석에 필요한 기생 성분

  • signoff deck

    검증 규칙과 실행 조건

  • ECO result

    설계 수정과 재검증 결과

PROCESS

  1. STA
  2. DRC / LVS
  3. IR / EM
  4. Approval

OUTPUT

  • Approved layout DB

    최종 승인을 받은 레이아웃 DB

  • signoff report

    STA·DRC/LVS·IR/EM 검증 결과

  • release checklist

    릴리스 기준과 최종 점검 내역

단계별 핵심 과정

  1. 01
    STA closure

    추출 RC와 조건을 반영해 setup·hold 등 타이밍 제약의 충족 여부를 확인합니다.

  2. 02
    DRC / LVS

    레이아웃의 기하학적 규칙과, 레이아웃에서 추출한 회로의 연결 일치를 확인합니다.

  3. 03
    IR / EM

    전압 강하와 전류 밀도에 따른 신뢰성을 점검합니다.

  4. 04
    Release approval

    검증 리포트와 체크리스트를 모아 최종 승인합니다. 미충족 항목은 ECO 후 다시 확인합니다.

승인된 레이아웃과 검증 증빙을 Tapeout에 전달합니다.

08

Tapeout

승인된 레이아웃을 제조용 데이터로 패키징해 전달

INPUT

  • Approved layout DB

    Signoff에서 승인된 설계 DB

  • signoff report

    최종 검증 결과와 증빙

  • release checklist

    릴리스에 필요한 최종 점검표

PROCESS

  1. GDSII / OASIS
  2. Release package
  3. Foundry handoff

OUTPUT

  • GDSII

    GDSII / OASIS 제조용 레이아웃

  • foundry handoff package

    파운드리 전달 데이터와 문서 묶음

  • release version data

    고정된 릴리스 버전과 이력

단계별 핵심 과정

  1. 01
    GDSII / OASIS export

    레이아웃의 계층과 기하 정보를 제조에 전달할 데이터 형식으로 내보냅니다.

  2. 02
    Foundry checklist

    Signoff 결과, 전달 항목, 버전 정보를 확인하고 릴리스 패키지를 정리합니다.

  3. 03
    Mask data handoff

    파운드리의 전달 절차에 따라 데이터를 넘겨 마스크 준비와 제조로 연결합니다.

전달된 제조 데이터가 웨이퍼 제조와 제품화로 이어집니다.

09

Fab / Package / Test

설계 데이터를 웨이퍼와 패키지 칩으로 완성

INPUT

  • GDSII

    제조에 사용할 레이아웃 데이터

  • foundry handoff package

    파운드리 전달 패키지

  • release version data

    승인된 제조 릴리스 버전

PROCESS

  1. Wafer fab
  2. Package
  3. Production test

OUTPUT

  • Packaged chip

    패키지 조립을 마친 칩

  • yield data

    양산 테스트 결과와 수율 데이터

  • final product

    테스트를 거친 최종 제품

단계별 핵심 과정

3D 구조를 불러오는 중입니다.

드래그로 회전 · 휠로 확대 · 방향키로 회전 구조와 흐름을 보는 개념 모델

  1. 01
    Wafer fabrication

    반복적인 공정을 통해 웨이퍼 위에 다수의 다이를 형성합니다.

  2. 02
    Package assembly

    다이를 패키지 기판과 연결하고 보호 구조를 조립해 외부 접속을 만듭니다.

  3. 03
    Production test

    제품 동작을 검사하고 결과를 분류합니다. 수율 데이터를 제품·공정 개선에 활용합니다.

완성된 제품과 테스트 결과가 다음 제품·공정 개선의 근거가 됩니다.

설계 흐름 크게 보기

Floorplan

Initial Physical Planning

칩의 전체 크기와 윤곽을 정하고, I/O 핀, 매크로(SRAM, IP), 전원망의 큰 배치를 먼저 잡는 초기 physical planning 단계입니다. 이후 단계의 혼잡도와 timing 품질을 크게 좌우하는 출발점입니다.

Chip Size Macro Power Grid

Placement

Standard Cell Placement

합성된 수많은 standard cell을 timing, 배선 혼잡도, 면적 효율을 고려해 적절한 위치에 배치하는 단계입니다. 이 단계가 흔들리면 이후 CTS와 Routing에서 문제가 크게 증폭됩니다.

Standard Cell Congestion Density

CTS

Clock Tree Synthesis

클럭 신호가 칩 내부의 플립플롭에 균형 있게 도달하도록 트리 형태의 분배망을 만드는 작업입니다. 핵심은 skew를 줄이고, clock latency와 전력 부담을 함께 제어하는 데 있습니다.

Clock Tree Skew Latency

Routing

Metal Interconnect

배치된 셀과 매크로의 핀을 실제 금속층으로 연결해 전기적 경로를 완성하는 단계입니다. timing뿐 아니라 제조 규칙까지 만족해야 하므로 DRC와도 밀접하게 이어집니다.

Metal Layer Connectivity DRC

RC Extraction

Parasitic Extraction

실제 배선에서 생기는 저항(R)과 커패시턴스(C)를 추출해 후반 timing 분석의 정확도를 높이는 작업입니다. Routing 이후 timing이 갑자기 나빠지는 이유를 이해할 때 함께 봐야 하는 핵심 개념입니다.

Parasitic R Parasitic C Post-Route

STA

Static Timing Analysis

시뮬레이션 벡터 없이 회로의 모든 timing path를 수학적으로 분석해 setup과 hold가 만족되는지 확인하는 작업입니다. 합성 이후에도, 배치배선 이후에도 반복해서 수행됩니다.

Setup Hold Timing Path

LEC

Logic Equivalence Check

RTL과 합성 netlist, 또는 최적화 전후 netlist가 논리적으로 같은 기능을 유지하는지 비교 검증하는 절차입니다. 구조가 바뀌더라도 기능은 같아야 하므로 ECO나 최적화 이후에 특히 중요합니다.

RTL vs Netlist Equivalence ECO Check

ECO

Engineering Change Order

마지막 단계에서 발견된 timing 위반이나 논리 오류를 전체 flow를 처음부터 다시 돌리지 않고 국소적으로 수정하는 방식입니다.

Local Fix Timing Fix Signoff Loop

DRC

Design Rule Check

레이아웃이 파운드리 공정 규칙을 어기지 않았는지 확인하는 물리 검증입니다. 배선 폭, 간격, via 규칙처럼 제조 가능성과 직결된 항목을 검사하므로 Routing 이후 signoff의 핵심 축이 됩니다.

Foundry Rule Spacing Manufacturability

LVS

Layout Versus Schematic

작성된 레이아웃의 연결 관계가 원래 의도한 회로도나 netlist와 같은지 비교하는 검증입니다. DRC가 규칙 준수 확인이라면, LVS는 연결 정합성 검증이라고 구분하면 헷갈림이 줄어듭니다.

Layout Netlist Connectivity

IR Drop

Voltage Drop Analysis

전원 공급점에서 부하 블록까지 전류(I)가 흐르는 동안 전원선의 저항(R)이 누적되면서, 시작점보다 끝단의 실제 전압이 더 낮아지는 현상을 분석하는 signoff 검증입니다. 전류가 큰 블록이나 power grid가 약한 구간에서 심해지며, local VDD 부족은 timing 악화와 기능 불안정으로 이어질 수 있습니다.

Power Grid Current I V = I x R

EM

Electromigration

금속 배선에 높은 current density가 오래 걸리면, 전자 흐름 방향으로 금속 원자가 서서히 밀려 이동합니다. 그 결과 한쪽에는 금속이 비어 void가 생기고, 다른 쪽에는 금속이 쌓여 hillock이 생기며, 장기적으로는 배선 단선이나 신뢰성 저하로 이어질 수 있습니다.

Current Density Reliability Void / Hillock

Std Cell Library

Standard Cell Timing Library

합성과 physical design이 기준으로 삼는 기본 셀 집합입니다. 각 셀의 기능, 지연, 전력, 면적 정보가 담겨 있어 synthesis가 gate를 고르고, STA와 PD가 timing 품질을 계산하는 출발점이 됩니다.

Cell Function Delay Power / Area

SDC Constraint

Synopsys Design Constraints

클럭, 입력 지연, 출력 지연, false path, multicycle path 같은 timing 조건을 정의하는 제약 파일입니다. 회로 자체를 바꾸는 파일은 아니지만, synthesis와 STA가 회로를 어떤 기준으로 해석할지 정해주는 핵심 입력입니다.

Clock I/O Delay False Path

UPF

Unified Power Format

저전력 설계 의도를 기술하는 파일로, power domain, isolation, level shifter, retention 같은 구조를 정의합니다. RTL만으로는 드러나지 않는 전력 동작 규칙을 synthesis, PI, PD 단계에 전달하는 역할을 합니다.

Power Domain Isolation Level Shifter

Signoff Deck

Foundry Rule / Check Deck

파운드리가 제공하는 최종 검증 규칙 세트로, DRC, LVS, RC extraction 같은 signoff 툴이 무엇을 어떤 기준으로 검사할지 정의합니다. 실무에서는 “공식 검증 기준서”에 가까운 의미로 이해하면 됩니다.

Foundry Rule DRC / LVS Official Check

GDSII

Graphic Data System II

GDSII는 Graphic Data System II의 약자로, 최종 physical layout을 제조용으로 담아낸 대표 데이터 포맷입니다. Signoff를 통과한 레이아웃 결과가 이 파일로 정리되어 파운드리로 전달됩니다.

Tapeout Data Layout Polygon Foundry Handoff

Sanity Check

Quick Consistency Check

본격적인 full run을 돌리기 전에 파일 연결, constraints, library, netlist 상태가 기본적으로 맞는지 빠르게 확인하는 사전 점검입니다. 큰 문제를 초기에 걸러 시간을 아끼는 기본 건강검진으로 이해하면 됩니다.
