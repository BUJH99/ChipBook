Clock와 reset 의미를 property와 맞춰야 한다. 과도한 assumption은 반례를 없애면서 실제 동작도 제거할 수 있다.

계산·동작 예

Ready가 영원히 낮아도 된다는 환경에서 모든 요청이 반드시 완료된다고 증명하려 하면 liveness 조건이 맞지 않는다. 필요한 fairness를 명시하고 그 가정이 실제 환경에서 성립하는지 확인한다.

코드와 동작

// One-cycle request acknowledgement in the chosen synchronous interface.
property p_request_ack;
    @(posedge iClk) disable iff (!iRstn)
        iReq |=> oAck;
endproperty
assert_request_ack: assert property (p_request_ack);
cover_request: cover property (@(posedge iClk) disable iff (!iRstn) iReq);
// A proof with an unreachable iReq can be vacuous; inspect assumptions and cover.

DUT가 보장해야 할 동작을 assume으로 넣어 검사를 순환 논리로 만들지 않는다.

잘못된 가정이 실제 버그를 숨기는 사례를 찾는다.
