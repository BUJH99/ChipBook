STA와 Clock · Reset 설계

17-1. Timing Path와 Timing Arc

Arrival time은 데이터가 도착하는 시각, required time은 제약에서 요구하는 시각이다. Slack의 부호와 의미는 setup/hold 같은 check 종류와 함께 읽어야 한다.

계산·동작 예

tCQ 0.5 ns와 data delay 6 ns이면 arrival은 6.5 ns다. Period 10 ns, skew 0.2 ns, uncertainty 0.1 ns, setup 0.4 ns이면 required는 9.7 ns, slack은 3.2 ns다.

Worst path의 요약 slack만 보고 어느 cell·net이 원인인지 생략하지 않는다.

보고서의 arrival/required/slack을 재계산한다.

17-2. Setup과 Hold

단순 single-cycle 경로에서 setup은 최대 지연, hold는 최소 지연을 본다. Positive capture skew는 setup에 여유를 주면서 hold에는 불리할 수 있다.

계산·동작 예

아래 계산기는 tCQ·setup·uncertainty·min delay·hold의 가정을 명시한다. Data 최대 delay를 줄여 setup을 고쳐도 최소 delay가 줄면 hold 문제가 생길 수 있다.

Clock period를 늘리는 것만으로 일반적인 같은-edge hold 위반이 해결된다고 설명하지 않는다.

서로 다른 위반 원인과 수정 방향을 구별한다.

17-3. Clock 정의와 분배

Ideal clock 단계와 propagated clock 단계의 latency·skew 가정도 다르다. Clock gating과 mux는 유효 edge와 mode별 관계를 검증해야 한다.

계산·동작 예

Divide-by-2 clock은 source period와 위상 관계를 가진다. 이를 관계없는 clock처럼 정의하면 필요한 synchronous path 분석을 놓칠 수 있다.

Clock 이름이 다르다는 이유만으로 비동기 clock group으로 처리하지 않는다.

분주·mux 조건에서 유효 clock 관계를 명시한다.

17-4. IO와 Source-Synchronous Timing

Source-synchronous 경로는 전달된 clock/strobe와 data의 상대 시간을 본다. Input/output delay의 max와 min 의미를 분리한다.

계산·동작 예

외부 송신기의 최대 tCO와 board 지연으로 input max delay를 구성하고 최소 조건도 별도로 계산한다. Board skew와 jitter를 어느 예산에 넣었는지 명시한다.

IO delay에 전체 clock period를 임의로 넣으면 실제 외부 계약과 무관한 분석이 된다.

외부 소자 요구까지 포함해 여유를 계산한다.

17-5. MMMC와 Variation

Variation 모델은 경로의 지연 차이를 보수적으로 반영하며 모델마다 가정이 다르다. 공통 clock 경로의 pessimism 처리도 분석 결과에 영향을 준다.

계산·동작 예

Functional mode에서 최악인 경로와 test mode에서 최악인 경로가 다를 수 있다. 모든 활성 mode/corner가 필요한 제약과 library를 사용하는지 확인한다.

하나의 slow corner가 모든 setup을, 하나의 fast corner가 모든 hold를 대표한다고 단정하지 않는다.

하나의 corner 통과를 전체 signoff로 오해하지 않는다.

17-6. Crosstalk과 기생 영향

Input slew와 load가 cell timing arc의 delay를 바꾸므로 배선과 cell을 함께 본다. Crosstalk 분석은 aggressor의 timing window도 고려한다.

계산·동작 예

인접한 두 net이 같은 방향과 반대 방향으로 전환하는 경우의 영향을 비교한다. Shield나 spacing 변경은 routing 자원과 다른 기생도 바꾼다.

Noise glitch와 delay 변화는 서로 다른 실패 경로이므로 하나의 수치로 섞지 않는다.

잡음과 지연 영향의 조건을 구별한다.

17-7. Reset Timing

Reset의 최소 pulse와 domain별 해제 순서도 중요하다. Reset 신호를 data setup/hold와 동일한 check로만 다루지 않는다.

계산·동작 예

Async assert, synchronous deassert 구조에서는 reset assertion과 release의 목적이 다르다. 각 domain의 유효 clock가 존재해야 release가 진행된다.

Reset tree를 일반 data net처럼만 최적화하면 pulse·skew·recovery/removal 조건을 놓친다.

reset 해제와 data setup/hold 검사를 구별한다.

17-8. Timing Closure 실습

Buffer·sizing·logic restructuring·pipeline·placement·routing은 서로 다른 비용을 가진다. ECO 뒤에는 관련 모든 check를 다시 실행한다.

계산·동작 예

Setup 위반에서 cell logic depth가 원인인지 wire/fanout이 원인인지 분리한다. Hold 수정으로 넣은 delay가 다른 mode의 setup을 악화시키지 않는지 본다.

보고서 한 경로만 좋아지고 새 worst path를 만들 수 있으므로 전체 결과를 비교한다.

한 경로 수정이 다른 corner에 주는 영향을 확인한다.
