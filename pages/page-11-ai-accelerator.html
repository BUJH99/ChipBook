11-1. Workload와 연산 그래프

모델의 연산 그래프 · CNN 예시

Workload는 연산 이름뿐 아니라 shape, batch, dtype, layout과 실행 순서로 정의합니다. 아래 그래프는 입력한 convolution 조건을 사용하며, ReLU·2×2 max pool·1,000-class 분류기를 뒤에 연결한 교육용 구성입니다.

표기: (N, C, H, W) = batch, channel, height, width. 입체 텐서 그림은 부피의 개념이며 그려진 칸 수가 실제 요소 수를 나타내지는 않습니다.

Convolution · 입력 window에서 출력 원소로

공간 window의 값과 weight를 곱하고 입력 channel에 걸쳐 합산합니다. Stride와 padding이 출력의 높이와 폭을 정합니다.

Y[n, cₒ, h, w] = Σcᵢ,i,j X[n,cᵢ,hs+i−p,ws+j−p] · W[cₒ,cᵢ,i,j]

Convolution의 GEMM 변환 · im2col

각 입력 window를 column으로 펼치면 weight와 matrix multiplication으로 표현할 수 있습니다. 그림의 칸 수는 축의 대응을 설명하기 위한 축약입니다.

연산량과 데이터 트래픽

GEMM C = A × B, A: M×K, B: K×N이면 MKN MAC입니다. M=N=K=16은 4,096 MAC = 8,192 Op입니다.

이 페이지는 1 MAC = 2 Op를 사용합니다. Bias·activation·pool·softmax의 연산량은 convolution MAC 합계에 포함하지 않습니다.

활성값과 가중치의 저장 크기

요소 수와 dtype당 byte를 곱합니다. 아래 합계에는 별도 workspace, padding 저장, alignment와 재사용 중복 traffic을 포함하지 않습니다.

주요 연산의 shape 변화와 하드웨어 관심사

Parameter 수는 전체 실행 연산량이나 중간 activation memory 크기와 다릅니다. 같은 조건의 shape와 dtype으로 비교합니다.

Convolution을 GEMM으로 매핑

입력·필터의 shape를 바꾸면 위 그래프, MAC 수, 저장량과 아래 매핑이 같은 조건으로 갱신됩니다. 명시적 im2col은 window를 복제하므로 원본 입력보다 큰 임시 저장 공간이 필요할 수 있습니다.

11-2. 수 표현과 양자화

주요 수 표현 형식의 bit 구성

부동소수점은 sign·exponent·fraction으로 범위를 표현하고, signed 정수는 정해진 bit 폭과 scale로 실수 값에 대응합니다. 연산과 저장에서 사용하는 형식을 각각 명시합니다.

FP32 · IEEE 754 binary32

부동소수점 식은 정규화 수에 해당합니다. 0, subnormal, infinity와 NaN은 exponent / fraction의 별도 규칙을 따릅니다. INT8의 하위 bit를 부호와 분리된 절댓값으로 해석하지 않습니다.

양자화 수식과 zero-point

실수 x를 scale s > 0과 정수 zero-point z로 양자화합니다. 반올림 방식과 clipping 범위를 reference model과 hardware가 동일하게 사용해야 합니다.

q = clip(roundties-to-even(x / s) + z, qmin, qmax)
x̂ = s · (q − z)
기호계약
x양자화 전 실수 값
s양의 scale · 이 예제는 per-tensor
z해당 signed 범위 안의 정수
qmin / qmax−2^(b−1) / 2^(b−1)−1
반올림가장 가까운 정수 · 정확한 중간값은 짝수

수치 예와 saturation

기본 예는 x=3.7, s=0.25, z=0입니다. 14.8을 15로 반올림해 q=15, x̂=3.75, 오차=0.05가 됩니다. 표현 범위를 벗어나면 끝값으로 포화됩니다.

z=0이면 실수 0은 정수 0에 대응합니다. z≠0이어도 실수 0을 표현하는 정수는 z입니다. −128…127 범위 자체는 바뀌지 않습니다.

Signed bit를 줄였을 때 zero-point가 새 범위를 벗어나면 입력 오류를 표시합니다.

입력·복원값과 복원 오차

왼쪽은 입력 x에 대한 원래 값 y=x와 복원값 x̂입니다. 오른쪽은 같은 입력에 대한 x̂−x를 표시합니다. Clipping이 없는 범위의 반올림 오차는 대체로 ±s/2 이내이며, saturation에서는 더 커질 수 있습니다.

11-3. MAC과 Processing Element

MAC Processing Element 구조

MAC은 곱셈과 누산을 수행합니다. PE는 operand register, local storage, valid·ready와 clear·reset 제어를 결합해 수락한 입력의 결과만 보관합니다.

구성 블록의 역할을 설명하는 입체 개념도이며 실제 cell 배치나 공정 stack을 뜻하지 않습니다.

Signed 부분곱과 가산 트리

8-bit 2의 보수 B의 최상위 bit는 음의 가중치를 가집니다. 아래는 pp[0…6] = A·bᵢ·2ⁱ, pp[7] = −A·b₇·2⁷로 분해한 산술 모델이며, 합계가 실제 A×B와 일치합니다.

수락 cycle과 accumulator

valid와 ready가 모두 1인 cycle만 누산합니다. Bubble과 stall은 같은 곱을 반복해서 더하지 않으며, 마지막 −1×6을 수락하면 19에서 13으로 바뀝니다.

코드와 동작

// cycle contract: accept = valid && ready
// A/B are signed; product and accumulator widths are explicit.
if (reset) {
    accumulator = 0;
    output_valid = false;
} else if (clear) {
    accumulator = 0;
} else if (accept) {
    accumulator += signed_product(a, b);
}

우선순위는 reset → clear → accept입니다. Product는 부호 확장하고 accumulator overflow 처리 방식을 별도로 정의합니다.

PE의 유효 연산 조건

곱셈 입력 정밀도와 부분곱 값

정수 A/B는 위 부분곱 그림에 사용하고, 실수 A/B는 선택한 bit 폭과 scale로 양자화한 뒤 곱합니다. 두 입력을 zero-point 0으로 양자화했으므로 곱의 복원 scale은 s²입니다.

행렬 곱과 한 PE의 dot product

출력 C[i,j]는 A의 i번째 row와 B의 j번째 column을 곱해 합한 값입니다. 아래 두 행렬과 출력 위치를 바꾸면 각 k의 product와 누적합을 확인할 수 있습니다.

11-4. Systolic Array

Systolic Array의 이웃 전달

A는 row를 따라 오른쪽, B는 column을 따라 아래로 전달합니다. 출력 partial sum은 각 PE의 local accumulator에 보관합니다.

선택한 PE의 내부 경로

C[i,j] ← C[i,j] + A[i,k] × B[k,j]

k = t − i − j가 0…N−1인 logical cycle에서만 유효한 MAC을 수행합니다.

4×4 array · 입체 구조

입체 그림은 4×4 구조 예시입니다. 왼쪽 회로와 아래 행렬은 선택한 입력 크기에 맞춰 바뀝니다.

입력 행렬과 관측 조건

2×2–4×4 signed INT8 행렬을 지원합니다. 관측 cycle을 직접 지정하고 특정 physical cycle부터 stall을 삽입하면 logical cycle과 누적 결과가 함께 유지됩니다. −1은 아직 입력을 수락하지 않은 상태입니다.

입력 행렬 A

입력 행렬 B

출력 행렬 C = A × B

Skew schedule과 결과 시점

PE(i,j)의 k번째 연산은 t=i+j+k입니다. N×N 행렬에는 3N−2개의 logical cycle이 필요하며 cycle 번호는 0부터 3N−3까지입니다. 4×4는 10 cycle, 2×2는 4 cycle입니다.

이 모델은 각 PE가 cycle당 한 MAC을 수행하고 출력이 local accumulator에 남는 구조입니다. 별도 output-drain protocol이나 pipeline stage를 추가하면 총 latency를 다시 계산해야 합니다.

Space-time · 모든 PE와 k

색이 칠해진 칸은 해당 logical cycle의 유효 연산입니다. 오른쪽 아래 PE의 마지막 k까지 전체 일정을 표시합니다.

11-5. Dataflow와 데이터 재사용

Reuse가 절약하는 경계

Output-stationary·weight-stationary·input-stationary는 어느 값을 local storage에 오래 유지하는지 설명합니다. Systolic 연결 구조와 dataflow는 같은 말이 아니며, 각 방식에는 operand와 partial sum을 이동시키는 매핑이 필요합니다.

Output-stationary · OS

각 PE가 한 C[i,j]의 partial sum을 유지하고 K 방향으로 누산합니다.

Weight-stationary · WS

PE 안의 W[k,j]를 유지합니다. A를 공급하고 K 방향으로 partial sum을 모읍니다.

Input-stationary · IS

PE 안의 A[i,k]를 유지합니다. B를 공급하고 K 방향으로 partial sum을 모읍니다.

대표적인 4×4 logical mapping을 보여 주는 개념도입니다. Stationary 값은 PE 내부 register에 표시했으며, 출력 수집과 multicast의 구현은 실제 array 구조에 따라 달라집니다.

Stationary 값과 local 경계의 이동량

아래 count는 inter-PE multicast가 없고 stationary object 하나가 전부 local storage에 들어가는 scalar 경계 모델입니다. A/B는 INT8, C는 INT32로 계산합니다. 각 접근은 read 또는 write 한 번이며 DRAM traffic 예측값은 아닙니다.

OS: A=B=MKN, C=MN. WS: B=KN, A=MKN. IS: A=MK, B=MKN. WS/IS의 C 접근은 MN(2K−1)로 정의합니다.

Row-stationary의 배치와 재사용

Row-stationary는 convolution row의 dot product를 PE에 배치하고 filter·activation·partial sum의 재사용을 저장 계층과 통신에 함께 조직합니다. 위 RS 예는 한 output의 세 row contribution을 설명하며, 전체 Eyeriss energy simulator가 아닙니다.

11-6. Tiling과 Loop Mapping

Tiling 개념과 데이터 흐름

큰 행렬을 local SRAM에 들어가는 tile로 나눕니다. A의 TM×TK, B의 TK×TN을 곱하고 C의 TM×TN partial sum을 모든 K tile에 걸쳐 유지합니다.

입체 tile의 칸 수는 개념 표현이며 실제 선택 크기는 왼쪽 축과 아래 예산으로 확인합니다.

Loop mapping과 데이터 재사용

Loop order는 같은 tile을 얼마나 오래 사용하는지 바꾸며, tile 크기는 parallelism과 storage 요구를 함께 바꿉니다. i0/j0/k0 순서에서는 C를 한 번 clear한 뒤 K tile 전체를 누산합니다.

for (int i0 = 0; i0 < M; i0 += TM)
  for (int j0 = 0; j0 < N; j0 += TN) {
    clear_accumulator_tile();
    for (int k0 = 0; k0 < K; k0 += TK) {
      load_valid_A_and_B_elements(i0, j0, k0);
      mac_only_inside_tensor_bounds();
    }
    store_valid_C_elements(i0, j0);
  }

Tile과 SRAM 예산

INT8 A/B, INT32 C의 기본 8×8×8 tile은 64 + 64 + 256 = 384 byte입니다. 아래 buffer 수는 A/B/C 한 세트 전체를 복제하는 명시적 조건이며, 실제 input만 double buffering하는 설계와 구분합니다.

Bytes = [(TM·TK + TK·TN)·b + TM·TN·4] × sets

Alignment, bank padding, descriptor와 metadata는 추가됩니다. 최대 tile 크기로 할당하며 tail의 유효 크기만큼 allocation이 자동으로 줄어든다고 가정하지 않습니다.

Tile 배치와 bank 충돌

메모리의 row stride와 접근 방향에 따라 동시에 요청한 word가 같은 bank로 몰릴 수 있습니다. 아래 8×8 표시의 진한 테두리는 첫 row 또는 첫 column의 동시 접근입니다.

Tail tile을 버리지 않기

전체 크기가 tile 배수가 아니면 마지막 row·column·K 항을 마스킹합니다. 계산 mask와 유효 memory byte를 같은 기준으로 처리하며, K tile이 바뀔 때마다 C를 clear하지 않습니다.

N=9, TN=8N tile 2개8, 1
K=7, TK=4K tile 2개4, 3

대역폭은 GB/s = 10⁹ byte/s입니다. 저장 용량의 축과 섞어서 높이를 비교하지 않습니다.

11-8. DMA와 Compute 중첩

두 buffer를 이용한 데이터 중첩

한 buffer에서 연산하는 동안 다른 buffer에 다음 tile을 적재할 수 있습니다. Load는 off-chip → SRAM, store는 SRAM → off-chip이며, 현재 consumer의 사용이 끝나기 전에 같은 buffer를 덮어쓰지 않습니다.

11-10. Sparsity와 Compression

희소 표현과 인덱스 구조

0이 많은 행렬을 저장할 때 value와 위치 정보를 분리합니다. 아래 기본 4×8 행렬은 32개 중 nonzero가 8개이므로 sparsity는 75%입니다. 입력을 바꾸면 CSR와 bitmap을 같은 행렬에서 다시 생성합니다.

희소 행렬 · 실제 nonzero 위치

파랑은 nonzero, 옅은 칸은 0입니다. 값 0을 저장하지 않는 대신 index 또는 bitmap이 필요합니다.

11-11. Attention과 KV Cache

Attention의 기본 흐름

Query와 Key의 유사도를 계산하고 mask·softmax를 거친 가중치로 Value를 합합니다. 각 query row의 softmax 합은 1이며, score shape와 output shape를 구분합니다.

구조 그림의 grid는 축의 대응을 설명합니다. 아래 수치 예는 작은 Q/K/V 행렬을 실제 계산하며 causal mask 선택을 결과에 반영합니다.

KV cache의 동작과 메모리 증가

Prefill은 여러 입력 token의 K/V를 준비합니다. Decode는 새 token의 K/V를 추가하고 기존 K/V를 재사용합니다. 저장 용량과 매 token에서 읽는 traffic은 서로 다른 지표입니다.

KV cache 용량

K와 V를 합한 단순 저장량입니다. GQA/MQA에서는 query head 수가 아니라 실제 KV head 수를 사용합니다.

11-12. Compiler와 Runtime

Compiler와 runtime의 경계

Compiler는 operator graph를 지원 kernel과 memory schedule로 변환합니다. Runtime은 buffer·명령·완료·오류를 관리합니다. Fusion은 중간 traffic을 줄일 수 있지만 register·SRAM 요구와 실행 제약을 바꿉니다.

def forward(x, residual):
    x = conv(x)
    x = bias(x)
    x = relu(x)
    return add(x, residual)

연산자 그래프와 fusion

Conv·Bias·ReLU를 합칠 때 dtype·scale·rounding·layout과 다른 consumer가 필요로 하는 intermediate 의미를 보존해야 합니다.

Loop schedule과 메모리 할당

for n in range(batch):
    for oc in output_channel_tiles:
        for y, x in spatial_tiles:
            wait_for_input_buffer()
            load_valid_input_tile(n, y, x)
            load_weight_tile(oc)
            compute_tile()
            postprocess_with_same_numeric_contract()
            store_valid_output_tile(n, oc, y, x)

Tile 크기는 PE 활용률, local SRAM, bank mapping, tail mask를 함께 고려합니다. In-place 실행은 이전 값의 마지막 consumer가 끝나고 alias와 크기 조건을 만족할 때만 허용합니다.

Tensor lifetime과 저장 경계

정수 RTL의 완료 기준은 bit-exact입니다. 허용 오차 모드는 근사 연산의 비교 원리를 위한 실습이며, 통과해도 실제 값의 차이는 계속 표시합니다.

Operand와 accumulator trace

선택한 C[row,column] = Σ A[row,k] × B[k,column]의 누산 과정입니다. 기본 PE(2,1)의 참조 값은 −6−5+4+12 = 5이며 k=2에서 −1을 주입하면 DUT 결과는 4입니다.

작은 NPU의 전체 구성과 확장 경계

먼저 작은 정수 GEMM core를 정확하게 계산하고, 이후 scratchpad·DMA·register·IRQ를 추가합니다. 아래는 확장 목표의 subsystem 구조이며, 다운로드하는 현재 SystolicCore는 parallel matrix port와 start/busy/done을 제공하는 계산 core입니다.

현재 다운로드 core의 실제 포트 계약

SystolicCore.sv의 구현을 기준으로 정리했습니다. 현재 core에는 MMIO register map, DMA 또는 IRQ controller가 포함되지 않으며, 별도 subsystem wrapper를 확장할 때 추가합니다.
