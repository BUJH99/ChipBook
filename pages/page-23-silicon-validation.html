실리콘 Bring-up과 수율 및 신뢰성

23-1. Bring-up 준비

Board revision, power rail, clock, reset, boot strap, debug 연결과 software image를 기록한다. 장비의 probe·bandwidth·reference 연결도 측정의 일부다.

계산·동작 예

전원 인가 전에 short와 rail 저항, 허용 공급 범위와 전류 제한을 확인한다. 초기 정상 파형과 실패 시 중단 조건을 정리해 재현 가능한 순서를 만든다.

측정 probe를 연결한 영향과 장비 설정을 생략하지 않는다.

검사 순서와 정상 기준을 미리 정한다.

23-2. First Boot

앞 단계의 정상 근거를 확보한 뒤 다음 단계로 이동한다. 로그가 없는 구간은 GPIO·trace·관측 register 같은 방법을 준비한다.

계산·동작 예

JTAG가 응답하지 않으면 boot code만 수정하기 전에 전원·clock·reset·pin/보안 상태를 확인한다. ROM 진입 이후 실패라면 실행 주소와 예외 원인을 좁힌다.

최종 증상인 화면 출력 실패만으로 display block부터 검사하지 않는다.

실패 지점 이전의 전제부터 확인한다.

23-3. 기능 검증과 계측

관측 사실과 원인 가설을 구분하고 동일 조건의 재현을 먼저 확보한다. Scope·logic analyzer·on-chip trace는 서로 다른 범위를 관측한다.

계산·동작 예

IRQ가 오지 않는 문제에서 source flag, mask, pending, CPU delivery를 나누어 검사한다. 각 단계의 timestamp와 설정을 남겨 한 경계씩 좁힌다.

로그에 오류가 없다는 것과 물리 신호가 정상이라는 것은 다르다.

추측과 측정 사실을 분리해 기록한다.

23-4. PVT Characterization

Shmoo plot은 두 조건의 pass/fail 분포를 보여주지만 workload·판정 기준·표본 수가 필요하다. 제품 spec과 guardband는 측정과 신뢰성 근거를 함께 반영한다.

계산·동작 예

Voltage–frequency grid를 sweep할 때 같은 test image와 error 기준을 유지한다. 특정 pattern에서만 생기는 실패도 별도로 기록한다.

한 chip의 짧은 test 결과를 모든 생산품의 한계로 일반화하지 않는다.

조건과 표본을 명시해 동작 범위를 해석한다.

23-5. 수율과 불량 분석

공간 패턴은 원인 후보를 좁히지만 그 자체가 원인 증명은 아니다. 불량 분석은 재현과 물리적 관측, 설계·공정 데이터의 연결을 요구한다.

계산·동작 예

Wafer edge에 fail이 몰릴 때 probe 접촉이나 공정 균일도 등 여러 가설을 구분한다. Lot·wafer·site·tester revision을 함께 비교한다.

Correlation을 바로 root cause로 보고 설계나 공정을 바꾸지 않는다.

상관관계만으로 공정 원인을 단정하지 않는다.

23-6. Reliability

BTI/HCI·EM·TDDB·ESD·latch-up은 원인과 검사 조건이 다르다. 가속 시험에서 사용 조건으로 해석할 때 모델과 적용 범위를 명시한다.

계산·동작 예

높은 온도나 전압에서 얻은 변화율을 사용 환경으로 옮기려면 해당 고장 메커니즘에 적합한 모델이 필요하다. 단순히 시간 비율만 나누지 않는다.

기능 test pass를 장기간 신뢰성 보장으로 표현하지 않는다.

가속 시험과 사용 조건의 차이를 설명한다.

23-7. Errata와 제품 개선

Firmware workaround, metal ECO와 respin은 적용 범위·위험·일정이 다르다. 수정 뒤에는 원래 실패뿐 아니라 관련 정상 동작도 재검증한다.

계산·동작 예

특정 DMA 길이와 alignment에서만 발생하는 오류라면 제한 조건과 검출 방법을 정확히 적는다. Workaround의 성능·기능 영향도 함께 기록한다.

해결됐다는 결론만 남기고 어떤 revision과 조건에서 확인했는지 생략하지 않는다.

고객 영향과 수정 범위를 일관되게 전달한다.
