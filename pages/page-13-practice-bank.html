27-1. 문제은행 탐색

문제은행은 정답을 고르는 연습과 근거를 설명하는 연습을 함께 제공한다.

기존 객관식 문항을 유지하고 확장 목차의 확인 문제를 분야별로 연결한다. 검색과 필터로 필요한 주제를 좁히고 관련 본문으로 돌아간다.

예제로 이해하기

같은 주제에서 개념 정의 문제와 파형·설계 판단 문제를 번갈아 풀고 오답의 원인을 기록한다.

오류를 해석하는 기준

문항을 외운 결과를 다른 조건의 설계 판단 능력과 동일하게 보지 않는다.

27-2. 파형과 코드 문제

파형과 코드는 시간·상태·폭·순서의 계약을 드러낸다.

전송이 수락된 cycle과 출력이 유효한 시점을 구별하고 register·memory의 갱신을 추적한다. 해설은 결과와 그 근거를 연결한다.

예제로 이해하기

AXI stall 중 payload 변화나 nonblocking pipeline의 한 cycle 지연을 설명하고 관련 절의 실습에서 다시 확인한다.

오류를 해석하는 기준

파형 모양만 보고 축·단위·edge 정의를 생략하지 않는다.

설계에서 확인할 것

정답뿐 아니라 오답의 이유를 설명한다.

학습 절 복습 문제

148개 학습 절의 질문을 먼저 설명하고 해설을 확인하세요. 북마크한 질문은 오답 복습에서 다시 볼 수 있습니다.

09.01 · 인터페이스의 경계와 계층
RTL 결과가 맞는데 링크가 실패할 수 있는 이유는?

RTL은 논리 계약을 확인하지만 실제 채널의 지연·반사·잡음과 수신 sampling margin은 별도 조건이다.

관련 본문에서 확인
09.02 · IO 전기적 기초
Open-drain의 high를 누가 만드는가?

출력 트랜지스터가 꺼졌을 때 pull-up과 부하의 RC 경로가 high를 만든다.

관련 본문에서 확인
09.03 · GPIO와 UART
8N1에서 유효 데이터보다 전송 bit가 많은 이유는?

수신 동기화를 위한 start/stop bit가 추가되기 때문이다.

관련 본문에서 확인
09.04 · SPI와 QSPI
CPHA=0에서 첫 데이터는 언제 준비되어야 하는가?

CS 활성 후 첫 sampling edge 이전에 유효해야 한다.

관련 본문에서 확인
09.05 · I2C와 I3C
주소 0x50 write가 파형에서는 0xA0인 이유는?

7-bit 주소 뒤에 R/W=0 bit를 붙여 8-bit 주소 byte를 만들기 때문이다.

관련 본문에서 확인
09.06 · DDR와 LPDDR
왜 pass window의 한쪽 끝보다 중앙을 선호하는가?

샘플 위치가 이동할 때 양쪽 경계까지의 여유를 확보하기 위해서다.

관련 본문에서 확인
09.07 · PCI Express
작은 payload에서 실효 대역폭이 낮아질 수 있는 이유는?

payload 대비 header·관리 traffic과 전송 간격의 비중이 커지기 때문이다.

관련 본문에서 확인
09.08 · USB와 Type-C 및 PD
Type-C 케이블이 연결되면 항상 같은 USB 속도가 나오는가?

아니다. 케이블과 양쪽 장치의 지원 capability 및 협상 결과가 함께 결정한다.

관련 본문에서 확인
09.09 · Ethernet
Buffer를 무한히 늘리면 처리율 부족이 해결되는가?

지속적인 도착률이 서비스율보다 크면 backlog가 계속 증가하므로 해결되지 않는다.

관련 본문에서 확인
09.10 · MIPI 카메라와 디스플레이
동일 해상도·fps에서 RGB888과 RAW12의 payload는 같은가?

아니다. 활성 pixel당 24 bit와 12 bit이므로 이 조건에서는 RGB888이 두 배다.

관련 본문에서 확인
09.11 · CAN과 LIN
CAN 중재에서 패배한 노드가 frame을 망가뜨리지 않는 이유는?

송신한 recessive와 관측한 dominant의 차이를 감지해 이후 송신을 중단하기 때문이다.

관련 본문에서 확인
09.12 · SerDes와 PHY
EQ를 강하게 하면 무조건 좋아지는가?

아니다. 잡음 증폭, 오차 전파, channel 및 adaptation 조건 때문에 최적점이 달라진다.

관련 본문에서 확인
09.13 · SI와 PI 및 보드 채널
TDR의 시간축에서 반사가 보이는 위치는 무엇과 관련되는가?

신호의 왕복 지연과 전파 속도로 계산한 불연속까지의 거리와 관련된다.

관련 본문에서 확인
09.14 · 인터페이스 선택과 성능 예산
Raw 8 Gb/s는 8 GB/s인가?

아니다. bit를 byte로 바꾸면 1 GB/s이며 overhead를 적용하면 payload는 더 작다.

관련 본문에서 확인
09.15 · Bring-up과 디버그 실습
Training 실패 직후 첫 확인 대상으로 무엇이 적절한가?

전원·reference clock·reset·설정의 정상 근거와 실패 단계 로그를 확인한 뒤 channel/PHY 세부로 좁힌다.

관련 본문에서 확인
10.01 · 제품 요구와 시스템 예산
Latency 20 ms인 pipeline이 60 fps를 처리할 수 있는가?

단계가 겹쳐 충분한 throughput을 내면 가능하다. 첫 결과 지연과 연속 결과 간격을 구분해야 한다.

관련 본문에서 확인
10.02 · SoC 구조와 IP 분할
IP 연결표에 최소한 무엇을 기록해야 하는가?

신호/프로토콜, 폭, 주소, clock/reset domain, 전력 조건, 순서와 오류 처리 책임이다.

관련 본문에서 확인
10.03 · 주소 공간과 레지스터 설계
W1C bit를 0으로 지우려 하면 어떻게 되는가?

보통 해당 bit는 그대로다. W1C는 지울 위치에 1을 쓰는 계약이다.

관련 본문에서 확인
10.04 · 메모리 계층과 일관성
Coherent DMA이면 모든 쓰기 순서도 자동으로 원하는 대로 보장되는가?

아니다. 데이터 가시성과 descriptor/doorbell 등의 ordering 계약은 구분해서 지켜야 한다.

관련 본문에서 확인
10.05 · DMA와 데이터 이동
READY가 0인 cycle에서 transferred byte는 증가하는가?

수락 handshake가 없으므로 증가하지 않는다.

관련 본문에서 확인
10.06 · 인터럽트와 타이머
Mask 상태에서 event가 발생하면 항상 버려지는가?

그렇지 않다. source/controller의 pending 저장 계약에 따라 이후 unmask 때 전달될 수 있다.

관련 본문에서 확인
10.07 · Clock과 Reset 통합
PLL lock 신호만 있으면 downstream reset을 즉시 풀어도 되는가?

lock의 clock domain·안정성·동기화와 해당 block의 reset 해제 조건을 함께 확인해야 한다.

관련 본문에서 확인
10.08 · Boot와 펌웨어 및 드라이버
Timeout 후 바로 새 전송을 시작해도 되는가?

이전 DMA가 정지·취소되었는지와 buffer ownership이 회복되었는지 먼저 확인해야 한다.

관련 본문에서 확인
10.09 · Interconnect와 QoS
Queue를 늘리면 latency가 항상 줄어드는가?

더 많은 요청을 보관할 수 있지만 대기 시간이 늘 수도 있다. 처리율과 지연을 함께 봐야 한다.

관련 본문에서 확인
10.10 · 전력 도메인과 저전력 통합
Retention 없이 전원을 껐다 켜면 register 상태가 유지되는가?

상태 보존을 보장할 수 없으며 reset·재초기화 경로가 필요하다.

관련 본문에서 확인
10.11 · 보안과 안전의 통합 접점
CPU의 MMU 설정만으로 모든 DMA 접근을 막을 수 있는가?

DMA 경로에는 별도 주소 변환·보호 장치나 interconnect 정책이 필요할 수 있다.

관련 본문에서 확인
10.12 · 시스템 성능과 병목
Amdahl 분석에서 연산을 무한히 빠르게 해도 전체 speedup이 제한되는 이유는?

가속하지 않은 직렬 구간의 시간이 남기 때문이다.

관련 본문에서 확인
10.13 · 시스템 통합 검증
가장 작은 system smoke test에는 무엇을 넣는가?

기동, 주소 접근, 한 번의 실제 데이터 이동, 완료 관측과 결과 비교를 포함한다.

관련 본문에서 확인
10.14 · 제품 사례와 설계 리뷰
아키텍처 리뷰에서 그림 외에 필요한 것은?

요구별 수치 예산, 인터페이스 계약, 가정, 실패 처리와 검증 근거다.

관련 본문에서 확인
11.01 · Workload와 연산 그래프
M×K와 K×N 곱셈에서 결과 shape와 MAC 수는?

결과는 M×N이며 총 M×N×K MAC이다.

관련 본문에서 확인
11.02 · 수 표현과 양자화
입력 8 bit 두 개를 곱하면 누산기도 8 bit면 충분한가?

아니다. 곱의 범위와 누산 횟수에 필요한 여유를 고려해야 한다.

관련 본문에서 확인
11.03 · MAC과 Processing Element
Stall 중 operand가 유지될 때 매 cycle 누산해도 되는가?

수락된 연산이 아니면 누산하면 안 된다. 같은 항이 중복될 수 있다.

관련 본문에서 확인
11.04 · Systolic Array
PE(1,1)는 왜 PE(0,0)보다 늦게 첫 연산을 하는가?

Operand가 row와 column 방향으로 이동하는 추가 지연이 있기 때문이다.

관련 본문에서 확인
11.05 · Dataflow와 데이터 재사용
Output-stationary가 주로 줄이려는 데이터 이동은?

출력 partial sum을 local에 누산해 반복적인 외부 저장과 읽기를 줄이려 한다.

관련 본문에서 확인
11.06 · Tiling과 Loop Mapping
M=17, tile M=8이면 몇 개의 row tile이 필요한가?

ceil(17/8)=3개이며 마지막 tile의 유효 row는 1개다.

관련 본문에서 확인
11.07 · 메모리 계층과 Bandwidth
용량과 bandwidth를 따로 확인해야 하는 이유는?

저장할 수 있는 byte 수와 한 cycle에 읽고 쓸 수 있는 byte 수는 다른 제약이기 때문이다.

관련 본문에서 확인
11.08 · DMA와 Compute 중첩
Ping-pong buffer가 하나의 buffer보다 유리한 조건은?

전송과 연산이 겹칠 수 있고 서로 다른 buffer를 안전하게 사용할 때다.

관련 본문에서 확인
11.09 · Activation과 후처리
함수 근사 오차가 작으면 모델 정확도도 반드시 같아지는가?

그렇지 않다. 누적 오차와 입력 분포, 모델 민감도에 따라 달라진다.

관련 본문에서 확인
11.10 · Sparsity와 Compression
Sparse 표현이 dense보다 커지는 경우가 있는가?

Index·pointer·padding 비용이 줄인 value byte보다 커지면 가능하다.

관련 본문에서 확인
11.11 · Attention과 KV Cache
Sequence length를 두 배로 늘리면 이 단순 KV 저장량은?

다른 조건이 같으면 두 배가 된다.

관련 본문에서 확인
11.12 · Compiler와 Runtime
Operator fusion의 잠재적 단점은?

Local resource 요구가 커져 병렬성이 줄거나 scheduling·지원 형식 제약이 커질 수 있다.

관련 본문에서 확인
11.13 · 성능과 전력 분석
Arithmetic intensity를 계산할 때 어떤 byte를 세는가?

분석하는 memory 경계를 실제로 통과하는 byte를 센다. SRAM과 DRAM 경계를 혼용하지 않는다.

관련 본문에서 확인
11.14 · 검증과 디버그
Stall이 없는 테스트만 통과하면 어떤 문제가 남는가?

데이터 유지·valid 정렬·중복 누산·buffer ownership 문제가 아직 드러나지 않았을 수 있다.

관련 본문에서 확인
11.15 · 작은 NPU 설계 실습
최소 end-to-end 성공 조건은?

설정·입력 전송·연산·출력 반환·완료 통지가 모두 일치하고 모든 출력이 reference와 맞아야 한다.

관련 본문에서 확인
12.01 · 반도체와 전하
평형 PN 접합에 내부 전기장이 있어도 순전류가 0인 이유는?

Drift와 diffusion 성분이 서로 균형을 이루기 때문이다.

관련 본문에서 확인
12.02 · MOS 구조와 동작
MOSFET의 saturation은 BJT의 saturation과 같은 동작인가?

소자 구조와 영역 정의가 다르므로 용어만으로 동일시할 수 없다.

관련 본문에서 확인
12.03 · 공정의 기본 순서
Lithography와 etch의 역할 차이는?

Lithography는 선택 패턴을 만들고 etch는 그 패턴에 따라 대상 재료를 제거한다.

관련 본문에서 확인
12.04 · FEOL과 BEOL
같은 net의 배치·배선이 바뀌면 무엇을 다시 확인해야 하는가?

기생 RC, timing, coupling과 전류 밀도 등 영향을 받는 항목을 재확인한다.

관련 본문에서 확인
12.05 · Planar와 FinFET 및 GAA
GAA 구조를 평가할 때 gate 제어 외에 볼 것은?

접촉과 기생 성분, 변동, 열, 제조 가능성과 실제 library의 회로 특성이다.

관련 본문에서 확인
12.06 · 공정 변동과 소자 모델
Corner sweep만으로 local mismatch 영향을 모두 확인할 수 있는가?

아니다. 소자 간 상대적 차이를 나타내는 mismatch 모델과 분석이 필요하다.

관련 본문에서 확인
12.07 · 특수 소자와 기술 접점
센서의 소자 특성과 signal conditioning을 함께 보는 이유는?

소자의 출력 범위·잡음·비선형성이 필요한 증폭·변환·보정 조건을 결정하기 때문이다.

관련 본문에서 확인
13.01 · CMOS Inverter
부하 capacitance를 늘리면 무엇이 변하는가?

전환에 필요한 전하와 지연, switching energy가 증가하는 방향으로 영향을 준다.

관련 본문에서 확인
13.02 · CMOS 논리 게이트
NAND의 NMOS network가 직렬인 이유는?

A와 B가 모두 high일 때만 출력에서 ground까지 이어져야 하기 때문이다.

관련 본문에서 확인
13.03 · 지연과 구동 능력
Buffer 추가가 upstream 경로에 주는 영향은?

입력 capacitance와 배선이 달라져 앞단 delay와 전력도 변한다.

관련 본문에서 확인
13.04 · 회로의 전력
전압을 10% 낮추면 단순 dynamic power 비율은?

Liberty·SPEF·UPF 조각은 필드를 읽기 위한 축약 예제이며 완전한 tool 입력 파일이 아닙니다. 실제 실행에는 library·net·supply와 분석 조건을 모두 연결합니다.

E · 규격과 원문 자료

개념을 확인할 공개 원문입니다. 실제 설계에서는 사용한 규격의 revision, 소자 datasheet와 tool/library version을 고정하고 해당 절을 함께 기록합니다.

이 교재의 자료 확인일은 2026-10-18입니다. 연결된 표준 모음 페이지는 원문을 찾는 출발점이며, 특정 규격의 인증이나 모든 최신 조항의 구현을 뜻하지 않습니다. PCIe 계산은 Gen1~5, I2C 실습은 7-bit 주소, NPU 예제는 INT8·INT32로 범위를 제한합니다.
