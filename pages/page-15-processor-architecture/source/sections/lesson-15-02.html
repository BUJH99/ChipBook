Data hazard는 이전 결과 의존성, control hazard는 다음 실행 위치와 관련된다. Forwarding·stall·flush의 조건을 명확히 정의해야 정확성을 보존한다.

계산·동작 예

Load 결과를 바로 다음 명령이 사용할 때 해당 결과가 필요한 stage에 제때 도착하는지 확인한다. 없으면 bubble이나 다른 scheduling이 필요하다.

Stage 수가 늘면 무조건 실행 시간이 줄어드는 것은 아니다. Clock 이득과 hazard penalty가 함께 변한다.

data/control hazard를 재현하고 해결한다.
