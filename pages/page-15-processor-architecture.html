15-1. ISA와 마이크로아키텍처

마이크로아키텍처는 그 계약을 구현하는 pipeline, 실행기와 저장 구조다. 같은 ISA를 서로 다른 구조로 구현할 수 있으며 기능 호환성과 성능은 다른 질문이다.

계산·동작 예

Load 명령을 보면 주소 계산 → translation/protection → cache/memory 접근 → register 갱신으로 나눌 수 있다. ISA는 결과를 규정하지만 내부 cycle 수는 구현과 상황에 따라 달라진다.

명령 이름을 안다는 것과 실제 cache·pipeline 동작을 예측할 수 있다는 것을 혼동하지 않는다.

ISA 동작과 구현 방식을 구별한다.

15-2. Pipeline과 Hazard

Data hazard는 이전 결과 의존성, control hazard는 다음 실행 위치와 관련된다. Forwarding·stall·flush의 조건을 명확히 정의해야 정확성을 보존한다.

계산·동작 예

Load 결과를 바로 다음 명령이 사용할 때 해당 결과가 필요한 stage에 제때 도착하는지 확인한다. 없으면 bubble이나 다른 scheduling이 필요하다.

Stage 수가 늘면 무조건 실행 시간이 줄어드는 것은 아니다. Clock 이득과 hazard penalty가 함께 변한다.

data/control hazard를 재현하고 해결한다.

15-3. 고성능 CPU 기법

Register renaming은 이름 의존성을 줄이고 ROB 같은 구조는 architectural state의 순서 있는 완료를 지원한다. Speculation 실패는 복구가 가능한 상태로 관리해야 한다.

계산·동작 예

오래 걸리는 load 뒤의 독립 산술 명령을 먼저 실행할 수 있어도 예외와 architectural commit 순서는 별도로 유지한다.

먼저 실행한 명령이 항상 먼저 software-visible state를 바꾼다고 해석하지 않는다.

성능 이점과 상태 관리 비용을 설명한다.

15-4. 메모리 시스템

TLB는 주소 변환 결과를 cache하는 구조이며 data cache와 역할이 다르다. 다중 agent의 cache coherence와 memory ordering은 계층 구조와 함께 검토한다.

계산·동작 예

4-line direct-mapped cache, 16-byte line에서 주소 0과 64는 같은 index에 대응하므로 서로 다른 tag가 교체된다. 가까운 주소라도 line boundary를 넘는지 확인한다.

Cache miss를 모두 DRAM 접근으로 간주하면 다른 cache level과 prefetch 등의 경로를 생략하게 된다.

주소 변환과 캐시 일관성을 구별한다.

15-5. GPU와 벡터 처리

Branch divergence와 memory access 패턴은 실제 활용률에 영향을 준다. Memory coalescing은 인접한 요청을 효율적인 transaction으로 모으는 것과 관련된다.

계산·동작 예

Thread들이 연속 주소를 읽는 경우와 stride가 큰 주소를 읽는 경우를 비교한다. 필요한 payload가 같아도 실제 memory transaction 수는 달라질 수 있다.

Thread 수가 많다는 사실만으로 모든 연산기가 항상 유효한 일을 한다고 가정하지 않는다.

병렬화 수준과 실제 효율 차이를 설명한다.

15-6. DSP와 특화 연산

Fixed-point 구현은 binary point 위치, coefficient 정밀도, 누산 폭과 saturation을 정의해야 한다. Pipeline은 latency를 늘리면서도 sample 처리 간격을 줄일 수 있다.

계산·동작 예

4-tap FIR은 각 출력에 네 곱의 합을 사용한다. 입력과 coefficient가 작아 보여도 누산의 최악 범위와 rounding 위치를 계산한다.

소수점 위치가 다른 값을 단순 정수 덧셈으로 합치면 scale 오류가 생긴다.

수치 오차와 처리율을 함께 계산한다.

15-7. 구조 선택과 성능 비교

작은 batch의 latency와 큰 batch의 throughput은 다른 평가다. End-to-end 비용에 전송과 변환도 포함한다.

계산·동작 예

같은 kernel을 가속해도 입력을 복사하고 결과를 동기화하는 비용이 크면 짧은 작업에서는 CPU 경로가 유리할 수 있다.

서로 다른 정밀도와 sparse 조건의 peak 수치를 직접 순위로 만들지 않는다.

이름이나 peak 수치만으로 우열을 정하지 않는다.
