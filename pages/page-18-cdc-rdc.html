Part 18

CDC와 RDC

18-1. Metastability와 도메인

동기화기는 해소 시간을 제공해 다음 단계로 전파될 확률을 낮춘다. MTBF 분석은 소자 특성·clock·data 활동·해소 시간의 가정에 의존한다.

계산·동작 예

두 flip-flop을 직렬로 놓고 첫 stage 출력이 안정될 시간을 확보한다. 첫 stage 출력에 fanout을 넓히거나 중간 조합논리를 넣으면 의도한 경계가 달라진다.

디지털 waveform에 X가 없다는 이유로 metastability 위험이 없다고 판단하지 않는다.

디지털 그림을 아날로그 metastability 시뮬레이션으로 오해하지 않는다.

18-2. 단일 비트 동기화

짧은 pulse는 목적 clock에서 보이지 않을 수 있어 pulse stretching, toggle 또는 handshake가 필요하다. 원천·목적 clock 속도뿐 아니라 event 사이 간격도 고려한다.

계산·동작 예

10 ns 폭 pulse를 20 ns 주기의 목적 clock로 관측하면 위상에 따라 놓칠 수 있다. Event를 toggle로 바꾸면 변화가 sampling될 때까지 상태를 유지할 수 있지만 event rate 제한이 남는다.

코드와 동작

(* ASYNC_REG = "TRUE" *) logic Event_d1, Event_sync;
always_ff @(posedge iClkDst or negedge iRstn) begin
    if (!iRstn) begin
        Event_d1   <= 1'b0;
        Event_sync <= 1'b0;
    end else begin
        Event_d1   <= iEvent_cdc;
        Event_sync <= Event_d1;
    end
end
// Single-bit level only. Pulse width and reset release need separate contracts.

모든 single-bit signal에 동일 2FF를 붙이면 사건의 수가 보존된다고 가정하지 않는다.

짧은 pulse가 유실되는 조건을 찾아 대안을 고른다.

18-3. Handshake와 Multi-bit CDC

Handshake는 data를 안정적으로 유지한 구간을 제어 신호로 전달한다. Reconvergence는 독립적으로 동기화한 신호가 다시 결합하면서 원래 관계를 잃는 문제다.

계산·동작 예

Binary counter가 0111→1000으로 변할 때 bit별 동기화 결과가 순간 다른 값 조합이 될 수 있다. Gray code는 한 번에 한 bit만 바뀌는 속성을 특정 목적에 사용한다.

코드와 동작

// Source must hold payload while waiting for acknowledgement.
property p_payload_stable;
    @(posedge iClkSrc) disable iff (!iRstn)
        (Req && !Ack_sync) |=> $stable(Data);
endproperty
assert_payload_stable: assert property (p_payload_stable);

Gray code도 배선 지연과 전송 방식의 제약 없이 모든 bus CDC를 해결하지 않는다.

비트별 2FF만으로 bus 일관성이 보장되지 않음을 설명한다.

18-4. Asynchronous FIFO

상대 pointer를 Gray code 등으로 전달해 full/empty를 판단한다. Pointer wrap과 reset 관계, memory port의 동작을 함께 정의해야 한다.

계산·동작 예

Depth 4에서 다섯 번째 write를 막고, read 후 공간이 다시 생기는 과정을 본다. 실제 async 구현에서는 상대 pointer가 동기화 지연 뒤 반영되므로 flag가 보수적으로 유지될 수 있다.

코드와 동작

// Binary pointer is used for memory indexing; Gray crosses the domain.
assign PtrWrBin_d  = PtrWrBin + (WriteValid && WriteReady);
assign PtrWrGray_d = (PtrWrBin_d >> 1) ^ PtrWrBin_d;
// Synchronize the Gray pointer before computing the remote empty/full view.
// This fragment does not include the full/empty equation or physical skew constraints.

브라우저의 논리 queue 동작을 아날로그 metastability까지 검증한 것으로 해석하지 않는다.

wrap·동시 read/write·reset에서 데이터 순서를 보존한다.

18-5. RDC와 Reset 전략

같은 clock를 쓰더라도 독립 reset 때문에 신호가 비동기적으로 바뀔 수 있다. Reset sequencing, isolation과 state handshake를 확인한다.

계산·동작 예

송신 block만 reset되면 valid·control이 갑자기 바뀌어 수신 block이 잘못된 transaction으로 해석할 수 있다. 수신 측의 reset 여부와 contract를 함께 본다.

동일 clock이면 CDC/RDC 문제가 모두 없다고 가정하지 않는다.

동일 clock에서도 reset 경계 문제가 생기는 이유를 설명한다.

18-6. 분석과 검증 및 Waiver

Waiver는 위반을 숨기는 목록이 아니라 해당 구조가 안전하다는 조건과 증거다. Constraint와 mode 변화가 기존 waiver의 유효성을 바꿀 수 있다.

계산·동작 예

동기화된 request 동안 data가 안정적이라는 assertion과 event 중복·유실 검사를 붙인다. 구조 보고서의 경계를 실제 RTL과 연결한다.

오래된 waiver를 새 revision에 무조건 재사용하지 않는다.

waiver의 근거와 재검증 조건을 남긴다.
