Compiler와 runtime의 경계

Compiler는 operator graph를 지원 kernel과 memory schedule로 변환합니다. Runtime은 buffer·명령·완료·오류를 관리합니다. Fusion은 중간 traffic을 줄일 수 있지만 register·SRAM 요구와 실행 제약을 바꿉니다.

def forward(x, residual):
    x = conv(x)
    x = bias(x)
    x = relu(x)
    return add(x, residual)

연산자 그래프와 fusion

Conv·Bias·ReLU를 합칠 때 dtype·scale·rounding·layout과 다른 consumer가 필요로 하는 intermediate 의미를 보존해야 합니다.

Loop schedule과 메모리 할당

for n in range(batch):
    for oc in output_channel_tiles:
        for y, x in spatial_tiles:
            wait_for_input_buffer()
            load_valid_input_tile(n, y, x)
            load_weight_tile(oc)
            compute_tile()
            postprocess_with_same_numeric_contract()
            store_valid_output_tile(n, oc, y, x)

Tile 크기는 PE 활용률, local SRAM, bank mapping, tail mask를 함께 고려합니다. In-place 실행은 이전 값의 마지막 consumer가 끝나고 alias와 크기 조건을 만족할 때만 허용합니다.

Operator에서 명령까지

64×64 INT8 intermediate 한 경계를 외부에 write하고 read하면 8,192 byte입니다. 해당 경계를 합법적으로 fusion해 local에 유지하면 이 이동을 생략할 수 있습니다.

특정 operator가 모든 accelerator에서 미지원이라는 뜻이 아닙니다. 실제 backend의 지원 목록과 fallback 전송·형식 변환·동기화 비용을 확인합니다.
