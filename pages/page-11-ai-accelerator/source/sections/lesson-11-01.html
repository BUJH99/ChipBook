모델의 연산 그래프 · CNN 예시

Workload는 연산 이름뿐 아니라 shape, batch, dtype, layout과 실행 순서로 정의합니다. 아래 그래프는 입력한 convolution 조건을 사용하며, ReLU·2×2 max pool·1,000-class 분류기를 뒤에 연결한 교육용 구성입니다.

표기: (N, C, H, W) = batch, channel, height, width. 입체 텐서 그림은 부피의 개념이며 그려진 칸 수가 실제 요소 수를 나타내지는 않습니다.

Convolution · 입력 window에서 출력 원소로

공간 window의 값과 weight를 곱하고 입력 channel에 걸쳐 합산합니다. Stride와 padding이 출력의 높이와 폭을 정합니다.

Y[n, cₒ, h, w] = Σcᵢ,i,j X[n,cᵢ,hs+i−p,ws+j−p] · W[cₒ,cᵢ,i,j]

Convolution의 GEMM 변환 · im2col

각 입력 window를 column으로 펼치면 weight와 matrix multiplication으로 표현할 수 있습니다. 그림의 칸 수는 축의 대응을 설명하기 위한 축약입니다.

연산량과 데이터 트래픽

GEMM C = A × B, A: M×K, B: K×N이면 MKN MAC입니다. M=N=K=16은 4,096 MAC = 8,192 Op입니다.

이 페이지는 1 MAC = 2 Op를 사용합니다. Bias·activation·pool·softmax의 연산량은 convolution MAC 합계에 포함하지 않습니다.

활성값과 가중치의 저장 크기

요소 수와 dtype당 byte를 곱합니다. 아래 합계에는 별도 workspace, padding 저장, alignment와 재사용 중복 traffic을 포함하지 않습니다.

주요 연산의 shape 변화와 하드웨어 관심사

Parameter 수는 전체 실행 연산량이나 중간 activation memory 크기와 다릅니다. 같은 조건의 shape와 dtype으로 비교합니다.

Convolution을 GEMM으로 매핑

입력·필터의 shape를 바꾸면 위 그래프, MAC 수, 저장량과 아래 매핑이 같은 조건으로 갱신됩니다. 명시적 im2col은 window를 복제하므로 원본 입력보다 큰 임시 저장 공간이 필요할 수 있습니다.
