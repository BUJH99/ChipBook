Tiling 개념과 데이터 흐름

큰 행렬을 local SRAM에 들어가는 tile로 나눕니다. A의 TM×TK, B의 TK×TN을 곱하고 C의 TM×TN partial sum을 모든 K tile에 걸쳐 유지합니다.

입체 tile의 칸 수는 개념 표현이며 실제 선택 크기는 왼쪽 축과 아래 예산으로 확인합니다.

Loop mapping과 데이터 재사용

Loop order는 같은 tile을 얼마나 오래 사용하는지 바꾸며, tile 크기는 parallelism과 storage 요구를 함께 바꿉니다. i0/j0/k0 순서에서는 C를 한 번 clear한 뒤 K tile 전체를 누산합니다.

for (int i0 = 0; i0 < M; i0 += TM)
  for (int j0 = 0; j0 < N; j0 += TN) {
    clear_accumulator_tile();
    for (int k0 = 0; k0 < K; k0 += TK) {
      load_valid_A_and_B_elements(i0, j0, k0);
      mac_only_inside_tensor_bounds();
    }
    store_valid_C_elements(i0, j0);
  }

Tile과 SRAM 예산

INT8 A/B, INT32 C의 기본 8×8×8 tile은 64 + 64 + 256 = 384 byte입니다. 아래 buffer 수는 A/B/C 한 세트 전체를 복제하는 명시적 조건이며, 실제 input만 double buffering하는 설계와 구분합니다.

Bytes = [(TM·TK + TK·TN)·b + TM·TN·4] × sets

Alignment, bank padding, descriptor와 metadata는 추가됩니다. 최대 tile 크기로 할당하며 tail의 유효 크기만큼 allocation이 자동으로 줄어든다고 가정하지 않습니다.

Tile 배치와 bank 충돌

메모리의 row stride와 접근 방향에 따라 동시에 요청한 word가 같은 bank로 몰릴 수 있습니다. 아래 8×8 표시의 진한 테두리는 첫 row 또는 첫 column의 동시 접근입니다.

Tail tile을 버리지 않기

전체 크기가 tile 배수가 아니면 마지막 row·column·K 항을 마스킹합니다. 계산 mask와 유효 memory byte를 같은 기준으로 처리하며, K tile이 바뀔 때마다 C를 clear하지 않습니다.

N=9, TN=8N tile 2개8, 1
K=7, TK=4K tile 2개4, 3
